## What I build

Small, sharp tools — automation, MCP servers, and programs that drive other programs.
The kind of thing you reach for once and then keep in your toolbox.

## How I work

The thing I care about most is **verification**.

A lot of software reports success because a process exited `0`, not because the work
actually happened. Once you start checking the output instead of the return code, you
find that gap everywhere — in libraries, in command-line flags, in documented features
that quietly do nothing.

So my tools check their own results, and my write-ups show the reproduction rather than
just the conclusion.
